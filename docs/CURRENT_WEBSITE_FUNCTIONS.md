# 当前网站功能说明

> 文档快照：2026-07-25
>
> 对应前端：`website/src/app/App.tsx`
>
> 当前性质：可交互的 React 前端原型，尚未连接真实 API

## 1. 产品定位

网站面向校友群体，以价值观问卷为基础生成个人价值画像，并在用户完成校友认证、开启匹配后，每七天推荐一位候选人。

核心体验是：

1. 注册或登录。
2. 完善个人资料并完成校友认证。
3. 完成 24 道核心价值问卷。
4. 查看 7 个价值维度的结果与历史版本。
5. 获取每周推荐，比较双方价值维度并按规则查看联系方式。
6. 对推荐表示感兴趣、跳过、举报或暂停后续匹配。

## 2. 当前实现边界

当前网页已经实现页面、表单校验、交互状态、可视化和本地演示流程，但以下数据仍是前端模拟：

- 任意有效格式邮箱和任意非空密码均可登录。
- 注册、个人资料和认证结果没有写入服务器。
- 问卷草稿、结果、历史版本保存在浏览器 `localStorage`。
- 每周推荐、联系方式、匹配评分和下一次推荐日期均为 mock 数据。
- 举报、屏蔽、忘记密码、服务条款和隐私政策没有真实后端动作。
- Header/Footer 中“关于匹配、隐私政策、服务条款、联系我们”等入口仍为占位跳转。
- 页面路由是组件内状态，不是浏览器 URL 路由；刷新后会回到首页。
- 浏览器前进/后退和受保护页面深链尚不可用。

浏览器本地状态使用键：

```text
cg_state
```

结构包含 `user`、`questionnaire`、`archived`、`weeklyMatch` 和 `demoState`。

## 3. 用户状态

网站的功能展示由多组状态共同决定：

| 状态组 | 可选值 | 影响 |
| --- | --- | --- |
| 登录状态 | 未登录 / 已登录 | 决定能否访问主页、问卷、结果和推荐 |
| 匹配状态 | `active` / `inactive` | 暂停后不获得推荐，也不能查看当前推荐 |
| 问卷状态 | `not_started` / `in_progress` / `completed` | 决定主页展示开始问卷、继续填写或结果摘要 |
| 校友认证 | `unverified` / `verified` | 产品规则要求未认证用户不能获得或查看推荐；当前 mock 只在页面层隐藏 |
| 问卷记录状态 | `draft` / `current` / `archived` | 区分草稿、当前有效结果和历史结果 |
| 推荐反馈 | `unseen` / `viewed` / `interested` / `skipped` | 记录用户对当周推荐的操作 |

主页还提供仅用于设计演示的 A–E 状态切换：

- A：未填写问卷。
- B：问卷进行中。
- C：已完成、已认证且有推荐。
- D：已完成、匹配开启且无推荐；模拟数据默认仍未认证，手动切到“认证后”才显示等待态。
- E：已完成但匹配已暂停。

设计切换器和认证前/后按钮应在接入真实后端后移除，或只在开发环境显示。

## 4. 页面与功能

| 路由 | 访问条件 | 当前功能 |
| --- | --- | --- |
| `/` | 公开 | 产品介绍、流程说明、问卷介绍、价值维度预览、示例推荐和隐私说明 |
| `/register` | 公开 | 邮箱、密码、确认密码、可选社交账号、条款勾选和前端校验 |
| `/login` | 公开 | 邮箱密码登录、记住我、忘记密码入口；当前接受任意凭据 |
| `/dashboard` | 已登录 | 认证、个人资料、头像、匹配开关、问卷进度、结果摘要和本周推荐 |
| `/questionnaire` | 已登录 | 24 题分阶段作答、自动保存、重要题目选择和提交确认 |
| `/questionnaire/complete` | 已登录 | 提交成功、价值画像预览、开启匹配和进入结果页 |
| `/results` | 已登录 | 当前价值画像、7 个维度、重要题目、全局图和重做入口 |
| `/results/archive` | 已登录 | 当前与历史问卷版本列表、只读展开查看 |
| `/matches/current` | 已登录 | 已认证、匹配开启且有推荐时显示详情；否则显示认证、暂停或等待空态 |

### 4.1 注册与登录

注册页当前校验：

- 邮箱必须符合基本邮箱格式。
- 密码至少 8 位。
- 两次密码必须一致。
- 必须勾选服务条款。
- 微信、Instagram、小红书和 LinkedIn 为可选字段。

密码强度提示只根据长度计算。“记住我”复选框、服务条款、隐私政策和忘记密码按钮均尚未连接页面或接口。

### 4.2 校友认证

前端提供三种认证方式：

- 校友或教育邮箱。
- 学信网认证。
- 已认证校友推荐码。

当前只检查邮箱/推荐码输入是否为空，随后立即把用户标记为已认证；学信网方式连凭据输入都不需要，点击确认即成功。真实实现需要支持待审核、成功、失败和过期等状态。

### 4.3 个人资料

已实现：

- 头像上传，仅接受图片，限制 5 MB。
- 浏览器端将图片最长边缩至 900 px，并转为质量 0.82 的 JPEG Data URL。
- 自我介绍，最多 300 字。
- “对 TA 的期待”，最多 300 字。
- 简介和期待支持编辑、保存和取消。

头像选择后会立即写入本地状态，取消资料编辑不会撤销头像变更。真实后端应改为文件上传与对象存储 URL，不能把大段 Data URL 写入用户表。

### 4.4 匹配开关

用户可以暂停或恢复匹配。暂停后的产品语义是：

- 不再收到每周推荐。
- 不出现在其他人的推荐中。
- 不能查看当前推荐。
- 问卷结果和历史记录保留。

### 4.5 核心价值问卷

问卷采用 1–7 的光谱选择，共 24 题、5 个阶段：

| 阶段 | 名称 | 题号 |
| --- | --- | --- |
| 1 | 生活方式 | 1–6 |
| 2 | 人生方向 | 7–12 |
| 3 | 社会与世界 | 13–18 |
| 4 | 情感与沟通 | 19–22 |
| 5 | 亲密关系 | 23–24 |

交互规则：

- 当前阶段全部作答后才能进入下一阶段。
- 答案或阶段变化后 1 秒自动保存。
- 通常可退出并从已保存阶段继续，但自动保存有 1 秒延迟；修改后立即退出时，最后一次变化可能因定时器被清除而丢失。
- 仅进入问卷且不作答，也会在 1 秒后创建空草稿。
- 24 题完成后，需要选择 3–5 个“最希望匹配对象与自己接近”的题目。
- 提交前有二次确认。
- 提交后生成当前有效结果；重做后旧结果应进入归档。

### 4.6 价值画像

当前前端展示 7 个维度，分数为所含题目答案的算术平均值：

| 维度 | 当前题号 |
| --- | --- |
| 稳定守序 ↔ 探索开放 | 1、2、3 |
| 独立空间 ↔ 社交联结 | 4、5、6 |
| 成就驱动 ↔ 生活从容 | 7、8 |
| 储蓄保障 ↔ 当下体验 | 9、10 |
| 竞争贡献 ↔ 平等合作 | 11、12 |
| 原则传统 ↔ 情境更新 | 14、15 |
| 直接表达 ↔ 关系照顾 | 20、21、22 |

显示百分比的换算为：

```text
percent = round((score - 1) / 6 * 100)
```

注意：题目 13、16、17、18、19、23、24 目前没有进入任何已展示维度。后端算法实现前必须确认是补充维度映射、作为独立匹配特征，还是从正式问卷中移除，不能静默丢弃。

当前可视化还有三个需要修正的实现细节：

- 源码中第一个维度名称写作“探索开放 ↔ 稳定守序”，但低分实际代表稳定、高分代表探索，名称顺序与分值方向相反。
- 全局雷达图只使用前 6 个维度，遗漏“直接表达 ↔ 关系照顾”。
- 推荐详情中的双方雷达图没有传入真实双方答案，仍在展示演示数据；条形维度对比才读取 `dimensionComparisons`。

### 4.7 结果与历史

结果页展示：

- 完成日期和问卷版本。
- 7 个维度的平均分。
- 用户选出的 3–5 个重要题目。
- 全局雷达/光谱图。
- 重做问卷入口。
- 固定的通用结果说明；当前不是算法生成的个性化解释。

历史页同时展示当前结果和归档结果。归档版本只读。

当前重做流程存在三处不一致：

- 结果页的“重新填写”会立即归档并清空当前问卷，但页面文案表达的是“新问卷提交成功前，旧结果仍然有效”。
- 主页上的“重新填写/重新开始”只跳转问卷，不创建或重置草稿，甚至可能继续修改当前结果。
- 清空后首次自动保存固定创建 `version: 1`，不会递增用户版本。

真实后端建议采用文案语义：创建新草稿时保留旧 `current`，新版本提交时再原子归档旧版本。历史页面中的记录都不可编辑，但“归档结果为只读”提示目前错误地只显示在当前结果展开项。

### 4.8 每周推荐

显示真实推荐详情的产品条件：

1. 用户已登录。
2. 校友身份已认证。
3. 匹配状态为 `active`。
4. 服务端存在当前有效推荐。

当前路由本身只检查是否登录。未认证、暂停或无推荐时仍能进入 `/matches/current`，但会看到相应空态。当前问卷提交逻辑不论认证和匹配状态都会先创建 `MOCK_MATCH`，页面随后再隐藏它；真实服务必须在候选和生成阶段执行资格检查。

推荐详情展示：

- 对方昵称、头像和推荐摘要。
- 7 个维度的双方分数。
- `close`（高度接近）、`complementary`（可以互补）、`discuss`（建议交流）分类。
- 最多三个主要共鸣领域和最多两个可探索话题。
- 邮箱及可选微信、Instagram；当前不显示注册时收集的小红书和 LinkedIn。
- 推荐日期和下一次刷新日期。

用户操作：

- 标记“我感兴趣”。
- 跳过本次推荐。
- 复制邮箱。
- 举报或屏蔽。

当前“感兴趣”和“跳过”都只更新内存且不会重新写入 `localStorage`，刷新后会丢失；跳过后推荐对象也没有被移除。打开详情不会把 `unseen` 更新为 `viewed`。举报原因按钮没有选择状态，提交不会保存举报或真正屏蔽用户。

完成页只检查匹配开关，不检查校友认证，所以未认证用户也可能看到“匹配已开启”；这属于当前原型与产品资格规则的差异。

## 5. 当前前端数据模型

前端类型的完整字段见 `website/src/app/App.tsx`，核心对象为：

- `AppUser`：账号、联系方式、匹配状态、问卷状态、头像、简介、期待和认证状态。
- `QuestionnaireResponse`：版本、答案集合、重要题号、阶段、时间和记录状态；草稿答案可以少于 24 题。
- `WeeklyMatch`：推荐对象、摘要、维度对比、日期和反馈状态。

后端返回字段建议保持 camelCase，以减少前端转换代码。正式接口契约见 [BACKEND_ALGORITHM_DATABASE_AGENT_GUIDE.md](./BACKEND_ALGORITHM_DATABASE_AGENT_GUIDE.md)。

## 7. 联调完成标准

前端从原型升级为可联调版本时，至少应满足：

- 刷新页面后能通过服务端会话恢复当前用户。
- 未登录用户无法读取任何受保护数据。
- 问卷定义、答案范围和维度映射由版本控制，不依赖散落的前端常量。
- 草稿保存幂等，网络重试不会产生多个问卷版本。
- 同一用户最多只有一个当前有效结果和一个进行中草稿。
- 未认证或暂停用户无法获得推荐，也不会出现在候选池。
- 联系方式只对当前有效推荐对象返回。
- 跳过、感兴趣、举报和屏蔽真实落库。
- 服务端与前端对“无推荐”“等待中”“认证失败”等状态有明确契约。
- 移除生产环境中的 A–E 演示切换器和任意凭据登录提示。
- 采用真实浏览器路由，支持刷新、深链和前进/后退。
- 修正 7 维可视化、分值方向和推荐详情中的演示雷达数据。
